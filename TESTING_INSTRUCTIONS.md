# Інструкція для тестування URL Share Build

## 🧪 Як протестувати новий функціонал

### Крок 1: Запуск проекту
З кореня проєкту виконайте:

```bash
yarn dev
```

Проєкт запуститься за адресою, надрукованою командою `yarn dev`.

### Крок 2: Тестування базового ділення

1. **Перейти на сторінку білдера:**
   - Відкрийте адресу сервера розробки та додайте `/build-planner`

2. **Вибрати клас та уміння:**
   - Натисніть на клас (наприклад, Gunslinger)
   - Натисніть на кілька пасивних умінь (червоні коло)
   - Натисніть на кілька активних умінь (сині кола)

3. **Згенерувати посилання:**
   - Натисніть кнопку "Share Build" (синя кнопка рядом з Save Build)
   - З'явиться модальне вікно з посиланням
   - Кнопка "Copy Link" скопіює посилання в буфер обміну

4. **Перевіримо формат посилання:**
   - Посилання мало б виглядати як:
     ```
   <origin>/build-planner#Gunslinger/p:Gimme%20a%20Reason,My%20Bad/a:1:Fire%20in%20the%20Hole|3:Heavy%20Metal
     ```
   - **ВАЖЛИВО:** Посилання ПОВИННО містити `#` а не `?`
   - Іменами умінь замість індексів

### Крок 3: Тестування завантаження білда з посилання

1. **Відкрийте новий браузер/вкладку:**
   - Вставте посилання що скопіювали на крок 4

2. **Перевірте чи білд завантажився:**
   - Повинні бути виділені ті ж уміння що ви вибрали раніше
   - Клас повинен бути правильний
   - Prestige чекбокс повинен бути установлений якщо були обрані престиж уміння

### Крок 4: Тестування різних сценаріїв

#### Сценарій A: Тільки пасивні уміння
```
#Gunslinger/p:Gimme%20a%20Reason
```
- Має завантажити Gunslinger з тільки одним пасивним умінням

#### Сценарій B: Тільки активні уміння
```
#Gunslinger/a:1:Fire%20in%20the%20Hole|3:Heavy%20Metal
```
- Має завантажити Gunslinger з активними умінями в колонах 1 і 3

#### Сценарій C: Пусто (тільки клас)
```
#Gunslinger
```
- Має завантажити Gunslinger без умінь

#### Сценарій D: Міст різних класів
Тестуйте з усіма класами:
- Dronemaster
- Exterminator
- Fixer
- Gunslinger
- Hellraiser
- Medic

- Vanguard

### Крок 5: Браузер Devtools перевірка

Відкрийте браузер Devtools (F12) → Console tab, ви повинні бачити:

#### При генерації посилання:
```
Encoded fragment: Gunslinger/p:Gimme%20a%20Reason/a:1:Fire%20in%20the%20Hole|3:Heavy%20Metal
```

#### При завантаженні посилання:
```
Build loaded from URL fragment: {
  passive: [...],
  active: {...},
  className: "Gunslinger"
}
```

### ⚠️ Червоні прапорці (якщо щось не працює)

1. **Посилання містить `?` замість `#`**
   - Проблема: код генерує старий формат
   - Рішення: перевірте чи змінили buildEncoder.js правильно

2. **Модальне вікно не показується**
   - Проблема: shareBuild() не викликається
   - Рішення: перевірте чи натиснули кнопку "Share Build"

3. **Посилання не завантажує белд**
   - Проблема: getBuildFromUrl() не викликається
   - Проблема: decodeBuildFromFragment() повертає null
   - Рішення: перевірте console для помилок

4. **Уміння не виділяються коректно**
   - Проблема: помилка при пошуку умінь в skillsTree
   - Рішення: проверьте чи імена умінь правильні в JSON

5. **Перевірте структуру вручну:**
   - Відкрийте F12 → Console
   - Введіть посилання як: `window.location.hash = "#Gunslinger/p:Gimme%20a%20Reason"`
   - Перезавантажте сторінку
   - Перевірте console для помилок

## 🔍 Дебаг мода

Якщо щось не працює, додайте цей код в браузер console:

```javascript
// Тестуйте кодування
import { encodeBuildToFragment, decodeBuildFromFragment } from '/src/utils/buildEncoder.js';

const test = {
  passive: [{name: "Test", isPassive: true}],
  active: {1: {name: "Test Active"}},
  className: "Gunslinger"
};

const encoded = encodeBuildToFragment(test, "Gunslinger");
console.log("Encoded:", encoded);

const decoded = decodeBuildFromFragment(encoded);
console.log("Decoded:", decoded);
```

Якщо обидва log'и виглядають нормально, проблема в іншому місці.
